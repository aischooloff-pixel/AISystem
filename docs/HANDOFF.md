## 1. Что сделано

Telegram-бот «Цифровой отдел продаж» для коучинговой практики Юлии Гейкиной.
Бот принимает клиентов из канала и личных сообщений, квалифицирует их через AI,
передаёт горячих Юлии с готовой карточкой и управляет воронкой через Airtable CRM.

Все **13 блоков** технического задания реализованы, протестированы и развёрнуты
на боевом сервере. Бот принимает живой трафик.

| Метрика | Значение |
|---|---|
| Код | 12 824 строки Python |
| Модули бота | 33 файла |
| Тесты | 293 (все зелёные), 19 тест-файлов |
| В том числе E2E | 50 сквозных прогонов |
| База знаний | 15 файлов, ~41 300 токенов |
| Коммитов | 20 |
| Живой трафик | 42+ контакта, 40+ комментариев |

### Блок 3 · Airtable CRM — закрыт

6 таблиц, 97 полей. CRUD по всем таблицам, дедупликация по `telegram_id`

| Touches | История касаний |

### Блок 4 · Промпты и слой AI — закрыт

Каждый ответ модели проходит валидацию по схеме. При `confidence < 85` решение
уходит Юлии автоматически. Перехват стоп-фраз: если модель употребила
запрещённую формулировку, ответ заменяется нейтральным.

Детерминистическая проверка `readiness_signal`: горячий статус возможен только
при наличии наблюдаемого признака готовности (просит записаться, спрашивает
цену/даты, готов оплатить, просит связаться лично, подтверждает готовность,
называет сроки). Без признака — максимум тёплый, решение за Юлией.

Модель заменяема через `OPENAI_MODEL` без правки кода. Сейчас `gpt-4o-mini`.

**Файлы:** `bot/prompts/` (5 модулей), `bot/services/ai.py`, `bot/utils/validators.py`

**Тесты:** `test_ai.py` — 32

### Блок 5 · /start, deep links, источник — закрыт

переопределяет источник. Клиент, уже переданный Юлии, не запускает автоматику.

**Файлы:** `bot/handlers/start.py`

**Тесты:** `test_block5_start.py` — 18

### Блок 6 · Квалификация — закрыт

FSM трёх сценариев:

- **Сценарий A** (готов покупать) — 2 вопроса → передача Юлии
- **Сценарий B** (описал проблему) — до 5 вопросов, досрочное завершение
- **Сценарий C** (информационный) — ответ без квалификации, переключение на B при повороте к проблеме

Вопросы задаются по одному. Карточка клиента содержит 8 блоков + timeline + кнопки.
Таймауты: 24 ч — напоминание, 72 ч — cold, 7 дней — задача Юлии.

Восстановление позиции диалога после рестарта — по `conversation_history` из CRM.
Схлопывание дублей сообщений перед отправкой в модель.

Автоматическая классификация темы запроса по таксономии Юлии (11 направлений
из продуктовой линейки).

Сообщение о диагностике после передачи — рассказ о формате встречи.

**Файлы:** `bot/handlers/qualification.py`, `bot/services/notifier.py`, `bot/states.py`,
`scripts/check_timeouts.py`

**Тесты:** `test_block6_qualification.py` — 18

## 4. Найденные и исправленные дефекты

За время разработки и живой эксплуатации обнаружены и устранены:

### Гонка дублей постов
Telegram выгрузил 13 комментариев одновременно. Все обработчики спросили «есть ли
пост?», получили «нет» — создали 9 записей. Исправлено per-key asyncio.Lock.

### Тесты, зависевшие от порядка запуска
11 тестов молча ничего не проверяли из-за `propagate = False` на логгере.
Исправлено фикстурой `app_caplog`.

### Зацикливание бота после рестарта
FSM-состояние живёт в MemoryStorage и умирает с процессом. При рестарте бот
начинал диалог с определения сценария — задавал тот же вопрос. Теперь позиция
восстанавливается по conversation_history из CRM.

### Преждевременный горячий статус
Модель считала число сообщений признаком готовности и поднимала до hot клиентов,
которые лишь описали ситуацию. Две причины: пример «взаимодействовал трижды»
в промпте и дубли сообщений из-за рестарта. Введён детерминистический
`readiness_signal` — без него hot невозможен. Дубли схлопываются.

### ContentType enum в CRM
В Python 3.12 `f"{message.content_type}"` даёт `ContentType.VOICE` вместо `voice`.
Юлия видела в CRM repr вместо значения. Исправлено `.value` в 4 файлах.

### Валидатор suggested_reply
Модель возвращала `null` при `needs_reply: false`, валидатор считал это браком.
23% комментариев уходили на ручную передачу без причины. Исправлено.

## 8. Архитектура безопасности

- Все секреты в `.env`, не в git, права 600
- Admin-команды доступны только `TELEGRAM_ADMIN_ID`
- Вебхук защищён секретным заголовком (401 без него)
- Парольный SSH отключён, root заблокирован
- Файрвол: только SSH + HTTP/HTTPS
- Нет eval/exec/pickle/subprocess в кодовой базе
- Стоп-фразы перехватываются до отправки клиенту
- AI не ставит диагнозов и не даёт советов
- Автопубликации комментариев нет — только через утверждение Юлией
- При confidence < 85 решение уходит Юлии
- Статус, установленный Юлией вручную, AI не перезаписывает
