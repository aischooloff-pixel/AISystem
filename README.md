# Geikina Bot — цифровой отдел продаж

Telegram-бот и AI-инфраструктура личного бренда Юлии Гейкиной (Sprint 1, MVP).

> Главный принцип: **ИИ не заменяет Юлию Гейкину. ИИ подготавливает клиента
> к качественному живому взаимодействию с ней.**

## Что делает система

- принимает обращения в Telegram, определяет сценарий (готов записаться /
  описывает проблему / информационный интерес) и квалифицирует клиента
  по утверждённым критериям;
- передаёт готовых клиентов Юлии карточкой с полной историей; при
  уверенности AI ниже 85% решение всегда за человеком;
- следит за комментариями в канале, находит потенциальных клиентов,
  предлагает ответы (публикация — только после утверждения);
- ведёт CRM в Airtable: контакты без дублей, история касаний, статусы
  с основаниями, задачи;
- напоминания при молчании (24 ч — один раз), еженедельный отчёт,
  автоматический бэкап.

## Стек

Python 3.11+ · aiogram 3 (webhook) · OpenAI API (gpt-4o-mini, через httpx) ·
Airtable REST API · systemd + cron на VPS. Вся автоматизация — в одной
кодовой базе, без no-code-прослоек.

## Структура проекта

```
bot/
  main.py            # вход: webhook, роутеры, middleware
  config.py          # настройки из .env (pydantic-settings)
  handlers/          # start (деплинки), qualification (FSM A/B/C),
                     # admin (команды Юлии), callbacks (кнопки карточки),
                     # comments (мониторинг комментариев)
  middlewares/       # pause_check — полная остановка автоматики
  services/          # ai (OpenAI), airtable (CRM), knowledge (база знаний),
                     # notifier (карточки Юлии), backup (экспорт CSV)
  prompts/           # системный промпт и промпты трёх функций AI
  knowledge/         # база знаний бренда (8 .md) — единственный источник
                     # знаний AI
  keyboards/ utils/  # клавиатуры, валидаторы (стоп-фразы!), логгер
scripts/             # setup_airtable --check, check_timeouts (cron),
                     # weekly_report (cron), backup.sh (cron), notify_backup
tests/               # 179 тестов, включая 15 контрольных сценариев
                     # (RESULTS.md)
docs/                # USER_GUIDE (для Юлии), SETUP (деплой), RECOVERY
logs.txt             # рабочий журнал разработки (НЕ логи приложения)
```

## Установка и запуск

Полная инструкция — [docs/SETUP.md](docs/SETUP.md). Кратко:

```bash
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env            # заполнить: Telegram, OpenAI, Airtable
.venv/bin/python -m scripts.setup_airtable --check
.venv/bin/python -m pytest tests/
.venv/bin/python -m bot.main    # или systemd: systemd/geikina-bot.service
```

## Переменные окружения

См. [.env.example](.env.example): Telegram (токен, ID Юлии, канал, группа,
webhook), OpenAI (ключ, модель), Airtable (ключ, база, имена таблиц),
логика (порог уверенности 85, таймауты 24/72 ч), прочее (логи, таймзона).

## Ключевые архитектурные решения

- **Безопасность решений AI**: строгая JSON-валидация каждого ответа
  модели, перехват запрещённых формулировок по нормализованному тексту,
  порог уверенности 85% с автопередачей Юлии, санитизация пользовательского
  ввода в промптах.
- **Ни одна ошибка не роняет бота**: все внешние вызовы с retry по
  таблицам ТЗ; окончательный сбой — понятное сообщение клиенту и
  уведомление/задача Юлии; пользователь никогда не видит traceback.
- **Дедупликация клиентов**: upsert по telegram_id с пер-пользовательским
  замком и сериализацией апдейтов; при сбое поиска запись не создаётся.
- **Приоритет человека**: ручные решения Юлии автоматика не
  переопределяет; переданные клиенты полностью выключают AI (middleware).
- **Разборчивость постфактум**: каждый запрос/ответ OpenAI — в app.log,
  каждое решение — в ai_decisions.log в фиксированном формате.
